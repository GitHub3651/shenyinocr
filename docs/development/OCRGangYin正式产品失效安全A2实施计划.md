# OCRGangYin 正式产品结果计划

## 1. 状态与范围

- 方案日期：2026-08-30。
- 当前状态：生产代码已按本计划完成实施，等待用户统一验证。
- 当前授权：用户已授权实施生产代码；不修改测试工程、Schema、UI 布局或 PLC 协议。
- 唯一目标：已取得正式 `ProductKey` 的可检测产品必须产生明确 OK 或 NG；系统无法可信检测时进入现有 Runtime Fault。
- 本文只规定产品结果与运行故障的边界，不改变字符算法、定位算法、阈值、模板格式或 UI 布局。

## 2. 最终结果合同

### 2.1 产品结果只有 OK 和 NG

```text
DetectionResult
  └─ AlgorithmVerdict::Ok / AlgorithmVerdict::Ng
```

- `AlgorithmVerdict` 只保留 `Ok` 和 `Ng`。
- `DetectionResult` 不包含独立运行状态字段。
- 默认判定为 `Ng`；完整通过当前模式全部检测条件时改为 `Ok`。
- 无定位、ROI 无效、OCR 空文本、二维码不可读和正常解码超时均返回 NG。
- ROI 无效不改变运行状态，也不发布模式专用警告。

### 2.2 故障不生成产品结果

```text
系统无法可信执行检测
  → 执行器抛出标准异常，或返回无效 DetectionCompletion
  → DetectionWorker::failureConsumer
  → Runtime Fault，停止接收新产品
```

故障不生成产品 NG，不进入普通统计、存图、PLC 或结果呈现事务；故障期间未形成正式结果的产品在统一停止收口时记为未确认。

### 2.3 取消只属于生命周期

队列和 Worker 的取消结果只描述停止、队列关闭和未执行工作，不生成正式产品结果，也不进入 `ResultService`。

## 3. NG 与 Fault 边界

| 模式 | NG 情况 |
|---|---|
| 钢印 | 无定位、日期 ROI 无效或越界、字符不符、现有钢印算法判 NG |
| OCR | 无定位、日期 ROI 无效或越界、识别为空或与目标不一致 |
| 字库 | 无定位、日期 ROI 无效或越界、字符匹配失败 |
| 二维码+三期 | 无定位、二维码/日期 ROI 无效、二维码不可读、正常解码超时、日期字符失败 |
| 纸巾 | 未找到纸卷/轮廓、粗糙度超限以及现有普通算法 NG |

每个 NG 完成一次总数/NG 统计、按设置存图、一次 NG PLC 请求或现有延迟 NG 入队，以及一次结果呈现。

以下情况进入 Runtime Fault，不返回产品 NG：无效工作项、定位成功后模板下标越界、运行模板或内部结构不一致、执行期 OCR/二维码引擎异常、预处理失败、Pipeline 或供应商引擎抛出异常、无效 completion。

## 4. 实施内容

1. 统一正式结果为 `Ok/Ng`，移除产品结果中的运行状态与额外结果策略字段。
2. 五个 Pipeline 对可判定的产品失败返回 NG；执行期异常进入 Worker Fault。
3. 二维码+三期日期子检测直接使用字库 Pipeline 的最终结果，不保留中间回调或包装结果。
4. Registry 和 ResultService 只接收合法 completion，并沿用唯一的统计、存图、PLC 和 UI 发布顺序。
5. 所有模式删除 ROI 专用警告出口；运行故障通过统一自动停止后的固定警告说明。
6. 保留队列、Worker 生命周期和 Runtime Fault 主链，不新增结果工厂、失败原因枚举、异常体系、结果管理层或第二套状态机。

## 5. 文件边界

计划修改范围为检测结果类型、五个 Pipeline、检测 Registry、ResultService、Runtime、MainWindow 以及对应开发说明；字符算法、定位方法和阈值、钢印重叠算法、纸巾算法、OCR/二维码识别规则、模板 Schema、设置文件、UI 布局、PLC 地址和值、延迟 NG 业务含义保持不变。

## 6. 验证门禁

### 6.1 静态门禁

- 生产结果只包含 `AlgorithmVerdict::Ok/Ng`。
- 合法 completion 只有一个 `ResultService::process()` 出口。
- 所有模式的 ROI 无效用例不发布 ROI 专用警告，也不改变运行状态。
- 二维码+三期不存在日期结果回调包装，日期子结果只读取一次最终判定。
- 队列和 Worker 生命周期仍能协作取消并正常退出。
- 不新增失败原因枚举、自定义异常体系、结果管理层或第二套状态机。
- 受保护算法、Schema、UI 和 PLC 文件无计划外差异。
- UTF-8、文件末尾换行和 `git diff --check` 通过。

### 6.2 用户统一验证

1. 在 Qt Creator 执行 qmake、Clean/Rebuild 和五模式软触发回归。
2. 使用真实硬触发、PLC、延迟 NG、引擎异常和运行故障自动停止完成统一验收。
3. 确认普通 NG 只产生一次产品结果，运行故障只触发统一自动停止和一次警告。
4. 确认统计、存图、PLC 和模板行为保持既有合同。

## 7. 完成条件

- 产品结果只存在明确的 OK 或 NG。
- 可判定的产品失败形成普通 NG；系统执行故障进入 Runtime Fault 并由统一停止链收口。
- 所有模式不再发布 ROI 专用警告。
- Agent 静态门禁通过，用户完成 Qt Creator、交互和真实设备验证。
