# 重要限制

## 1. 构建与验证

- 当前项目的 Qt、qmake、MSVC、OpenCV、相机 SDK、PaddleOCR 等环境以用户配置的 Qt Creator Kit 为准。
- Agent 默认不得直接或间接执行任何编译、链接或完整构建，不调用 `qmake`、`nmake`、`jom`、`msbuild`、`cmake --build`、`devenv` 或同类命令。
- 不得通过脚本、Qt Creator 命令行或 GUI 自动化触发构建，也不得自行编译、链接或运行主程序及测试目标。
- Agent 负责代码修改和轻量静态检查，包括：
  - 查看文件、搜索符号和清理旧引用；
  - 检查 `include`、声明与定义、信号槽签名；
  - 检查 `.pro`、`.pri`、`.ui`、`.qrc` 中新增、删除、移动和改名的文件；
  - 检查工程条目路径存在、无重复、无已删除文件残留；
  - 检查 UI XML、UTF-8、资源差异和 `git diff --check`。
- 完整构建、程序运行、人工交互以及相机、PLC 和现场验证由用户在 Qt Creator 或实际环境中执行。
- 静态检查通过不得表述为编译、运行或功能验证通过；用户确认前应如实标记为“代码已实施，待用户验证”。
- 只有用户在当前任务中明确授权具体构建目标时，才能例外执行相应命令；该授权不自动扩展到其他工程或后续任务。

## 2. 实现范围

- 不要过度设计。只实现用户明确要求的内容，以及使其正常成立所必需的配套工作，不增加未被要求的功能、流程、抽象、通用框架或顺手优化。
- 不要防御性编程。对项目自身控制且已有明确约束的输入，不叠加多余的校验、回退、兼容层或重复状态。
- 不要试图为几乎不可能出现或只有假设依据的场景兜底。只有当前需求、真实调用链、可复现问题或已有运行证据明确要求时，才增加对应处理。
- 不为假设中的未来需求提前泛化；优先原位修改和复用现有边界，避免过早抽象。
