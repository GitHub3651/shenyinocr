
## 3. 改造目标

1. 形成浅灰设备外壳、白灰面板、深色图像工作区和低饱和蓝色操作色组成的工业视觉语言。
2. 降低当前全局粗体造成的信息层级扁平化，让标题、操作、参数、状态和结果有明确主次。
3. 强化面板边界、输入区和数据区的可辨识度，同时避免消费级应用常见的大圆角、重阴影和动画。
4. 保持 OK、NG 在生产现场的远距离识别能力，并同时使用文字和颜色表达，不能只依赖颜色。
5. 直接提交八个主控按钮的静态线性 SVG，再由 QRC 和 `.ui` 使用；删除被替换后零引用的八个 PNG/ICO，并清理未启用历史主题，避免新旧资源并存。
6. 保持现有 1600×950 主设计尺寸，并在 1366×768 和 Windows 125%/150% 缩放下可用。

### 5.2 字体层级

- 字体族继续使用 `Microsoft YaHei UI`、`Segoe UI`、sans-serif。
- 普通正文和输入值：15px，字重 400 或 500。
- 普通按钮：15px，字重 600。
- 卡片和分组标题：14～15px，字重 600。
- 右侧导航文字：12～13px，字重 600。
- 识别内容：18～20px，字重 600。
- 统计值：22～25px，字重 600。
- 运行状态：24～30px，字重 700。
- 产品判定：42～48px，字重 800～900。
- 目标字符编辑框继续作为业务重点使用大字体，不跟随普通输入框缩小。

删除 `QWidget` 的全局粗体规则，禁止通过新的父级通配选择器再次让全部说明、单位和输入文字加粗。

### 5.3 形状与间距

- 普通输入框和按钮高度统一为 50 个 Qt 逻辑像素；当前确需更大触控区的控件按既有 `.ui` 约束保留。
- 八个主控 `QToolButton` 保留 85px 最小高度、48×48 图标和 `ToolButtonTextUnderIcon`，在 200px 主控区内继续等高扩展。
- 右侧导航固定 80px，入口固定或最小高度 68px，图标 28×28。
- 普通控件圆角 3～4px；主控按钮和关键状态块最大 6px；不使用大圆角卡片。
- 普通控件内部水平留白 8～12px；同组控件间距 6～8px；卡片间距 9～12px。
- 保留主控三个容器之间 18px 间距和 `1:2:1` 拉伸比例。
- 不增加阴影、浮层、玻璃效果、渐变大背景或滑入滑出动画。

### 5.4 样式唯一入口与文件职责

| 文件类型 | 唯一职责 | 禁止内容 |
|---|---|---|
| `app_theme.qss` | 承载全部控件颜色、字体、字号、字重、背景、边框、圆角、内边距、通用高度及 Normal/Hover/Pressed/Focus/Disabled/ReadOnly/Error/业务状态外观 | 不生成资源，不承载业务判断 |
| `.ui` | 保留父子结构、布局、拉伸、结构性边距/间距、`sizePolicy`、专用固定宽高、对象名、现有动态属性、文字和静态 QRC 图标路径 | 不写 `styleSheet`、`font`、`palette`、颜色、画刷、边框、圆角及控件通用视觉尺寸 |
| 静态 SVG | 只保存图标或网格自身的矢量路径、固有描边/填充色和透明背景 | 不包含控件 Hover、Pressed、Disabled、Checked 等 QWidget 状态样式，不生成状态副本 |
| `.cpp/.h` | 本轮零修改；现有代码继续提供既定业务状态属性，并由应用入口加载正式 QSS | 不新增颜色、字体、调色板、像素样式值、`setStyleSheet()`、运行时换色或动态绘图 |

静态 SVG 的路径、线宽和固有描边/填充色属于资源内容，不属于 QWidget 样式。控件表面、状态反馈和图标所在按钮的背景/边框仍全部由正式 QSS 控制；由于本轮禁止运行时换色，不为 Hover、Pressed 或 Disabled 生成额外图标文件。

## 6. 分区域设计

### 6.1 主窗口和分组容器

- 主窗口使用浅灰蓝设备外壳，不再让全部区域呈现同一片近白色。
- 左侧主控和图像区使用 `#F7F9FB`，右侧抽屉使用 `#EEF3F7`，形成清楚但低对比的功能分区。
- `QGroupBox` 使用 1px 钢灰边框和 3～4px 小圆角。
- 分组标题改为与所在面板同色的嵌边标题，文字使用深灰蓝；删除现有浅蓝胶囊底和统一蓝色标题。
- 标题只保留必要的边框断开和左右留白，不增加装饰线、图标或副标题。

### 6.2 主控操作台

- 保持打开相机、关闭相机、选择模板、制作模板、保存模板、分割字符、启动识别、停止识别的现有顺序和三组布局。
- 按钮使用白到浅灰的轻微纵向渐变、清晰边框和内侧高光，形成设备按钮质感。
- Hover 只改变背景和边框，不使用当前负边距上移效果，避免界面抖动。
- Pressed 使用更深背景和边框，不移动布局位置。
- Disabled 使用低对比灰色，继续由 `setEnabled(false)` 和 QSS `:disabled` 统一表达，禁用原因 Tooltip 保持不变。
- SVG 的固定语义色只约束默认图标资源；不要求 Qt 在禁用态自动将图标灰化，图标保持原色或被 Qt 灰化均可接受。禁用状态以按钮不可用性以及文字、背景、边框和 Tooltip 的整体表达为准。

### 6.3 主图像画布

- `InspectionImageCanvas` 只通过正式 QSS 将默认背景改为 `#202830`，边框使用更深的 `#111A22`。
- 直接新增 32×32 的 `canvas_background_grid.svg` 网格平铺资源，QSS 使用 `background-image` 和重复平铺形成 `#2B3640` 弱网格。
- 网格资源只作为控件背景，位于 QLabel 图像内容之后；不得在 C++ 中判断有无 Pixmap，不得修改 `paintEvent()`，不得动态绘制十字线或新增“等待图像”等显示文字。
- 真实图像、KeepAspectRatio 留白、模板锚点、二维码区域、钢印多边形、日期多边形和检测 Overlay 的现有显示与绘制实现全部保持，不借换肤调整其颜色、坐标、线宽、顺序或交互语义。
- 若 Qt 当前样式下静态背景图会覆盖真实图像，则取消网格，仅保留 QSS 深色背景；不得为保留网格而修改 C++ 或增加运行时判断。

### 6.4 产品判定和运行状态

产品判定继续使用唯一 `label_verdictResult` 和现有 `verdict` 属性：

| 属性 | 视觉 |
|---|---|
| `idle` | 浅灰背景、灰蓝文字，显示“等待检测”或“等待结果” |
| `ok` | 成功绿实底、白字，继续显示现有正确文案 |
| `ng` | 危险红实底、白字，继续显示现有错误文案 |

运行状态继续使用 `uiState=idle/ready/running/stopping/warning`：空闲中性灰、就绪浅绿、运行浅蓝、停止与警告浅橙。运行故障在界面层按 `stopping` 显示并由统一警告说明原因；不能增加只靠颜色识别的圆点或灯号。

### 6.5 右侧抽屉和导航

- 保持五入口导航、当前入口再次点击收起、单页显示及现有运行交互。
- 导航轨背景使用 `#DBE3EA`，入口之间使用细分隔线。
- 默认入口为透明背景和灰蓝文字；Hover 使用弱浅蓝；Checked 使用近白背景、主蓝文字和靠抽屉侧 4px 蓝色指示条。
- 抽屉页面使用 `#EEF3F7` 外壳和 `#F8FAFC/#FFFFFF` 内容卡片。
- 不固定复制参考 HTML 的 344px 抽屉宽度；继续使用当前主窗口拉伸关系和页面滚动能力，避免 1366×768 或高缩放下裁剪。
- 不新增悬停展开、遮罩、动画、手势或抽屉宽度持久化。

### 6.6 检测信息和参数页面

- 运行状态、识别内容、生产统计和当前模板继续保持现有内容与顺序。
- 统计卡片使用白色数值区、明确 1px 边框和 22～25px 数字；清零按钮继续为红色实底白字。
- 识别内容继续由外层分组提供区域边界，内部标签保持无独立边框。
- 设置卡片标题使用嵌边标题，表单标签、输入框和应用按钮按列对齐。
- 检测信息页的嵌套分组按层级分别处理：`groupBox_productionStatistics` 作为“生产统计”外层容器，使用透明背景和弱化/无边框；`groupBox_totalCount`、`groupBox_ngCount`、`groupBox_detectionDuration`、`groupBox_passRate` 作为四个白色统计卡片，保留独立边框和嵌边标题；`groupBox_runtimeStatus`、`groupBox_recognitionText`、`groupBox_currentTemplate` 按普通信息卡片处理。不得让通用 `QGroupBox` 规则再次给外层和内层叠加重复边框或标题胶囊。
- `QGroupBox::title` 的 `margin-top`、内边距和页面布局边距必须配套设置：外层标题不能压住内层卡片，内层标题不能被滚动区顶部裁剪；不通过增加固定高度改变现有内容顺序或滚动逻辑。
- 普通输入框、下拉框和按钮统一 50px 高度；长路径输入框继续扩展，浏览/选择按钮保持 80～100px 宽度。
- Focus 使用蓝色边框和极浅蓝背景；ReadOnly 使用灰白背景；Error 继续使用 `hasError=true` 的浅红背景和红边框。
- `scrollArea_inspectionInfo`、`scrollArea_detectionSettings`、`scrollArea_imageSettings`、`scrollArea_plcSettings`、`scrollArea_softwareSettings` 保持无外框，纵向滚动条改为 8px 钢灰滑块；滚动条选择器必须限定在这些 `QScrollArea` 对象内，不使用全局 `QScrollBar` 规则，不增加横向滚动条，也不改变文本编辑框和对话框的内部滚动条。

### 6.7 对话框

- 模板选择、模板保存和字符分割三个现有对话框自动继承正式 QSS。
- 表格、树、输入框、按钮、错误状态和标题使用同一工业视觉语言。
- `QMessageBox`、`QFileDialog` 和 Windows 原生目录选择器保持现有行为；不为视觉统一强制改用非原生对话框。
- 不增加新的确认步骤、提示文案、状态字段或对话框类型。

## 14. 风险与控制

| 风险 | 控制方式 |
|---|---|
| 删除全局粗体后重要信息不够醒目 | 对按钮、标题、统计、运行状态和判定逐类明确字重，不恢复通配粗体 |
| 控件高度统一后的空间占用 | 普通表单固定 50px，主控按钮和危险操作继续保留更大点击区域，并在生产显示器验证页面滚动和高缩放可用性 |
| 样式误写入 `.ui` 或正式 C++ | 用静态搜索检查 `styleSheet/font/palette/foreground/background/brush` 和 `setStyleSheet/setPalette/QColor`，计划内视觉属性只允许出现在正式 QSS；启动层唯一 QSS 加载和字符画布继承控件字体除外 |
| 深色画布网格覆盖真实图像 | 网格只作为 QSS 背景位于图像内容之后；若 Qt 当前样式下不能满足则取消网格，不修改 C++ |
| 画布视觉改动影响模板几何 | `InspectionImageCanvas` 的 `.cpp/.h` 零差异，只允许 QSS 背景变化 |
| 新 SVG 在 Qt 中缺失 | 统一 QRC 路径、XML 和工程资源检查，并由用户验证 Debug/Release |
| QRC 或 `.ui` 先引用尚不存在的图标 | VIS-1 先直接新增并确认九个实体 SVG 存在，VIS-3 才登记和引用 |
| 旧图标或历史主题误删仍在使用的资源 | 删除范围固定为第 8 节清单；删除前核对 QRC、`.ui`、QSS、C++ 和工程文件，删除后要求旧路径全仓零引用 |
| QSS 选择器误伤导航、嵌套分组或对话框 | 全局默认保持通用；生产统计外层/内层分组和五个页面滚动条使用明确对象名及父容器限定 |
| 设置页在高缩放下裁剪 | 保留现有 ScrollArea，验证 1366×768 和 125%/150% 缩放 |
| 视觉差异混入待验证 UI 功能 | VIS-0 记录基线并隔离其他差异，提交时只暂存本文计划内文件 |
