# OCRGangYin 许可证签发日期、日期回拨检测与到期提醒实施方案

## 1. 文档状态

- 方案日期：2026-09-25。
- 当前状态：代码已实施，静态检查通过，待用户统一验证。
- 权威范围：许可证签发日期、具体日期许可证的当前日期来源、上次检查日期记录、日期回拨判定、许可证异常分类、到期前 7 天启动提醒、启动及运行中的到期退出，以及许可证检查前的单实例门禁。
- 关联基线：授权模式、默认模式和设备绑定继续服从 `OCRGangYin许可证功能授权与许可证默认模式方案.md`；本方案新增签发日期字段并直接替换现有许可证格式。

## 2. 目标

许可证增加签发日期，具体日期许可证启动时使用本机上海日期检查签发日期：

1. `LicenseTool` 提供签发日期选择，打开工具时默认使用本机当天日期，并将日期作为独立加密字段写入 `license.ini`；
2. 程序读取当前 UTC 时刻并换算为上海日期；
3. 当前日期早于许可证签发日期时提示时间同步异常并禁止启动；
4. 本地只保存一个上次检查日期，本次日期早于上次日期时提示时间同步异常并禁止启动；
5. 到期前 7 天内每次启动都显示剩余天数，用户确认后继续使用；
6. 当前日期超过许可证到期日时明确提示许可证已到期，用户确认后退出；
7. 保留运行中每 24 小时检查一次的规则，允许跨过到期日后最多继续运行接近 24 小时；
8. 许可证文件、日期校验和设备绑定分别使用“系统初始化失败”“时间同步异常”和“绑定设备失败”提示；
9. 主程序在许可证检查前取得单实例标记，后续进程提示软件已在运行并退出。

日期判断继续按自然日执行。许可证到期日当天有效，从下一天开始到期。

## 3. 最终行为

### 3.1 长期有效许可证

`expires=permanent` 时：

- 正常解析并保留签发日期，设备首次绑定写回许可证时原样保留该字段；
- 许可证检查流程不获取当前日期，也不执行签发日期、到期日期或日期回拨判断；
- 不读取或写入上次检查日期；
- 不显示到期提醒；
- 不创建 24 小时到期检查定时器；
- 授权模式和设备绑定仍按许可证中的当前值进入现有启动流程。

### 3.2 具体日期许可证

每次启动按以下顺序处理：

```text
创建 QApplication 并取得单实例标记
  -> 取得失败：提示软件已在运行并退出
  -> 取得成功：读取并解析 license.ini
  -> 长期有效许可证：跳过后续日期流程
  -> 具体日期许可证读取当前 UTC 时刻并换算为上海日期
  -> 本次日期早于许可证签发日期：提示时间同步异常并退出
  -> 读取上次检查日期失败或记录损坏：提示时间同步异常并退出
  -> 本次日期早于上次日期：提示时间同步异常并退出
  -> 本次日期晚于上次日期或没有记录：保存本次日期，写入失败时提示时间同步异常并退出
  -> 本次日期大于 expiresDate：按许可证到期处理
  -> 完成首次设备绑定并重新读取许可证，或核对当前设备；失败时提示绑定设备失败并退出
  -> 剩余 0～7 天：显示提醒并继续启动
  -> 剩余超过 7 天：直接继续启动
```

单实例标记在创建 `QApplication` 后立即取得，并保持到主程序退出。只有取得标记的进程才读取许可证、读写 `runtime.dat`、查询设备信息或显示许可证启动提示；后续进程只显示“软件已在运行，请勿重复打开。”并退出。

具体日期许可证完成日期流程后才进入设备核对或首次绑定；长期有效许可证跳过日期流程后直接进入设备核对或首次绑定。日期记录在到期判断前更新。只要程序已经取得一个不早于历史记录的日期，就保存较晚日期；这样程序曾经确认已经超过到期日后，用户不能通过离线调早本机日期重新进入。

### 3.3 许可证签发日期

许可证格式直接升级为 `version=4`，增加一个独立加密字段：

```text
issuedDate=<yyyy-MM-dd>
```

`issuedDate` 表示许可证签发日期，也是具体日期许可证允许使用的最早上海自然日。字段名和值与其他许可证字段使用同一套独立字段加密方式，不以明文出现在文件中。

`LicenseTool` 生成许可证时写入 `issuedDate`。主程序解析所有 `version=4` 许可证时都读取并保留该字段，确保设备首次绑定后完整写回许可证；长期有效许可证的检查流程不使用该字段执行日期判断，也不获取当前日期。

`LicenseTool` 的签发日期和具体到期日期分别使用年、月、日三个独立下拉框。打开工具时签发日期默认值使用本机当天日期：

```cpp
QDate::currentDate()
```

允许生成许可证前分别选择年、月、日，生成时使用三个下拉框组成的日期。年份或月份变化时，日期下拉框按对应月份刷新，并在原日期超过新月份天数时选择该月最后一天。查看许可证时同时显示解密后的签发日期；文件信息中的有效期状态使用上海日期判断，不直接使用 `QDate::currentDate()`。

新格式不读取 `version=3`，不为缺失 `issuedDate` 的许可证补默认值，不保留旧格式解析、字段别名或转换逻辑。主程序与 `LicenseTool` 只读写 `version=4`。

## 4. 本机日期

具体日期许可证使用：

```cpp
QDateTime::currentDateTimeUtc().addSecs(8 * 60 * 60).date()
```

主程序的许可证日期统一按上海自然日判断，不依赖 Windows 当前显示时区。用户只修改系统时区不会改变判断日期；本次上海日期早于已记录日期时判定为回拨，同一自然日内调早不触发回拨判定。

取得当前上海日期后，具体日期许可证首先比较签发日期。当前日期早于 `issuedDate` 时直接返回时间同步异常，不读取或写入 `runtime.dat`，也不继续执行到期判断。主程序处理长期有效许可证时不进入日期获取和比较流程。

## 5. 上次检查日期

### 5.1 文件位置

日期记录固定保存为：

```cpp
QDir(QCoreApplication::applicationDirPath()).filePath(
    QStringLiteral("runtime.dat"));
```

`runtime.dat` 位于主程序目录，与 `license.ini` 同级。文件名不体现许可证、时间或日期用途。该路径是唯一保存位置，不创建其他目录，也不提供备用保存位置。

日期记录不进入：

- `license.ini`；
- `app_settings.json`；
- 模板文件；
- 日志文件。

“清空当前软件数据”继续只删除现有设置文件，不删除 `runtime.dat`。

### 5.2 文件内容

文件只保存一行大写十六进制密文，不写字段名、日期明文、版本号或其他内容：

```text
<加密后的大写十六进制文本>
```

写入时将日期按 `yyyy-MM-dd` 转为 UTF-8，使用 `runtime_guard.cpp` 内部固定密钥循环异或，再转为大写十六进制文本。读取时按相反顺序还原日期。

该处理只用于避免直接看出文件用途和日期内容。编解码直接作为 `runtime_guard.cpp` 的内部实现，不进入许可证编解码协议。

### 5.3 读写规则

- 文件不存在：使用本次日期创建文件；
- 本次日期等于记录日期：不写文件；
- 本次日期晚于记录日期：加密后使用 `QSaveFile` 原子覆盖；
- 本次日期早于记录日期：不改文件，返回 `TimeError`；
- 文件无法读取或无法解密为严格的 `yyyy-MM-dd` 日期：返回 `TimeError`；
- 应写入但无法在主程序目录创建或提交文件：返回 `TimeError`。

始终只有一个日期值。日期前进时覆盖旧值，不追加历史、不保存启动次数、不使用注册表、不建立第二份备份，也不回退到其他目录。

## 6. 到期判定

具体日期许可证先检查签发日期：

```cpp
currentDate < issuedDate
```

条件成立时按时间同步异常处理。条件不成立后再执行到期判断：

```cpp
currentDate > expiresDate
```

示例：

| 到期日期 | 当前日期 | 结果 |
|---|---|---|
| 2026-09-25 | 2026-09-24 | 有效，剩余 1 天 |
| 2026-09-25 | 2026-09-25 | 有效，今天到期 |
| 2026-09-25 | 2026-09-26 | 已到期 |

日期回拨返回 `TimeError`，超过许可证到期日返回 `Expired`。两者都阻止使用，但分别显示时间同步异常和许可证已到期提示。

## 7. 到期前 7 天提醒

启动检查通过后计算：

```cpp
const int remainingDays = currentDate.daysTo(expiresDate);
```

### 7.1 剩余 1～7 天

每次启动显示：

```text
标题：许可证即将到期

软件许可证还有 N 天到期。
到期日期：yyyy-MM-dd
请及时联系供应商续期。

按钮：确认
```

用户点击“确认”后继续进入主程序。

### 7.2 到期日当天

每次启动显示：

```text
标题：许可证即将到期

软件许可证今天到期。
今天仍可正常使用，请及时联系供应商续期。

按钮：确认
```

用户点击“确认”后继续进入主程序。

### 7.3 提醒范围

- 剩余超过 7 天不提醒；
- 7 天内每次启动都提醒；
- 不提供“今日不再提醒”；
- 不保存提醒状态；
- 运行过程中不重复显示到期前提醒。

## 8. 异常与到期退出

当前日期早于许可证签发日期、早于 `runtime.dat` 记录日期，或者 `runtime.dat` 无法读取、解析、创建或更新时显示：

```text
标题：时间同步异常

时间同步异常，请检查系统时间或联系供应商

按钮：确认退出
```

用户点击“确认退出”后直接结束启动。提示中不显示签发日期、历史日期、有效期或日期比较规则。

当前日期超过许可证到期日时显示：

```text
标题：许可证已到期

软件许可证已到期，无法继续使用。
请联系供应商续期。

按钮：确认退出
```

用户点击“确认退出”后直接结束启动，不创建主窗口、相机、PLC、OCR 引擎或检测服务。

WMI 初始化失败、无法取得有效设备码、首次绑定无法写回或重新读取 `license.ini`，或者许可证绑定设备与当前电脑不一致时显示：

```text
标题：绑定设备失败

设备绑定失败，请联系供应商

按钮：确认退出
```

`license.ini` 不存在或无法读取、版本不是 `version=4`、缺少必需字段或日期文本无法解析时显示：

```text
标题：系统初始化失败

系统初始化失败，请联系供应商

按钮：确认退出
```

## 9. 运行中检查

具体日期许可证继续创建固定 24 小时定时器。

定时器触发时：

1. 读取当前 UTC 时刻并换算为上海日期；
2. 当前日期早于许可证签发日期时提示时间同步异常并退出；
3. 读取并解密 `runtime.dat`；
4. `runtime.dat` 无法读取或解析、当前日期早于记录日期，或者新日期无法保存时提示时间同步异常；
5. 当前日期晚于记录日期时保存新日期；
6. 当前日期大于许可证到期日时按到期处理；
7. 日期检查未返回 `Valid` 时显示对应提示，用户确认后调用 `QCoreApplication::quit()`。

保留当前允许最多接近 24 小时延迟的行为。

## 10. 代码设计

### 10.1 `app/system_support/license/license_codec.h/.cpp`

`LicenseData` 增加：

```cpp
QDate issuedDate;
```

许可证版本直接改为 `version=4`。`issuedDate` 成为必需字段，并按以下固定逻辑顺序读写：

```text
issuedDate
expires
features
defaultMode
deviceBinding
deviceCode
```

写入和读取所有 `version=4` 许可证时都解析并保留有效的 `issuedDate`。具体日期许可证的到期日期由 `LicenseTool` 在生成前保证不早于签发日期。长期有效许可证只保留签发日期字段，不将其与当前日期或到期日期比较。不保留 `version=3` 或缺失字段的兼容分支。

删除 `LicenseDecodeResult::succeeded()`。主程序和 `LicenseTool` 的调用点直接判断 `LicenseCodecStatus`，不保留布尔转发接口。

### 10.2 `app/startup/runtime_guard.h`

许可证检查结果直接改为：

```cpp
enum class RuntimeGuardStatus
{
    Valid,
    Expired,
    TimeError,
    DeviceBindingError,
    Invalid
};
```

`RuntimeGuardResult` 保留授权结果和定时检查需要的日期：

```cpp
RuntimeGuardStatus status = RuntimeGuardStatus::Invalid;
bool permanent = false;
QDate issuedDate;
QDate expiresDate;
int remainingDays = -1;
```

同时保留现有的 `authorizedModeIds` 和 `defaultModeId`。删除现有 `bool valid` 和 `RuntimeGuardResult::succeeded()`，调用点直接判断 `status`，不保留旧布尔接口、转发函数或兼容包装。

`RuntimeGuard` 增加一个供 24 小时定时器直接调用的入口：

```cpp
static RuntimeGuardStatus checkRuntimeDate(
    const QDate &issuedDate,
    const QDate &expiresDate);
```

### 10.3 `app/startup/runtime_guard.cpp`

在现有文件内部原位实现：

- 当前 UTC 时刻转上海日期；
- `runtime.dat` 日期内容的简单加密、解密和原子写入；
- 签发日期比较；
- 日期回拨、到期和剩余天数判断；
- 启动检查和运行中检查共用的日期比较逻辑。

日期获取、日期记录和日期比较全部保留在现有 `runtime_guard.cpp` 中，不新增源码文件或公共组件。

`RuntimeGuard` 直接按 `detectionModeDescriptors()` 的顺序取得许可证中的授权模式，不重复校验 `LicenseTool` 已保证的授权集合、默认模式或设备绑定字段组合。具体日期许可证完成日期检查后，长期有效许可证跳过日期检查，随后完成设备首次绑定或核对。日期来源、日期记录、回拨和到期在同一文件的日期检查代码中完成，设备绑定失败返回 `DeviceBindingError`，许可证文件加载失败返回 `Invalid`。

`LicenseCodec` 负责许可证格式和日期文本解析。当前日期与签发日期、历史日期、到期日期的运行期比较集中在 `checkRuntimeDate()` 对应的唯一日期检查流程中。

在 `runtime_guard.cpp` 内保留一份接收 `currentDate`、`issuedDate` 和 `expiresDate` 的日期检查实现，负责签发日期、`runtime.dat`、回拨和到期判断。`RuntimeGuard::check()` 获取一次上海日期后调用该实现，并在结果为 `Valid` 时使用同一个 `currentDate` 计算 `remainingDays`；公开的 `RuntimeGuard::checkRuntimeDate()` 供 24 小时定时器调用，也只获取一次上海日期后进入同一实现。不重复获取当前日期，不增加时间服务类、结果类型或新的公开接口。

### 10.4 `app/startup/application_startup.cpp`

创建 `QApplication` 后立即构造 `SingleInstanceGuard` 并取得共享内存标记。取得失败时显示“软件已在运行，请勿重复打开。”并直接返回。取得成功的标记保持到 `ApplicationStartup::run()` 返回，因此许可证异常、到期提醒和主程序运行期间都不会进入第二个启动流程。

启动时直接按状态处理：

- `Invalid`：显示“系统初始化失败”并退出；
- `TimeError`：显示“时间同步异常”并退出；
- `DeviceBindingError`：显示“绑定设备失败”并退出；
- `Expired`：显示明确到期提示并退出；
- `Valid` 且 `remainingDays` 为 0～7：显示提醒后继续；
- `Valid` 且剩余超过 7 天：直接继续；
- 长期有效：直接继续。

现有退出提示函数最小修改为：

```cpp
void showRuntimeGuardExitMessage(
    const QString &title,
    const QString &message);
```

启动和运行中退出继续共用该函数，不新增提示类或第二套包装函数。

具体日期许可证的 24 小时定时器从 `RuntimeGuardResult` 保存 `issuedDate` 和 `expiresDate`，并调用 `RuntimeGuard::checkRuntimeDate(issuedDate, expiresDate)`。日期检查只返回 `Valid`、`TimeError` 或 `Expired`：`TimeError` 显示时间同步异常提示并退出，`Expired` 显示明确到期提示并退出。长期许可证不创建该定时器。定时器不计算 `remainingDays`，运行过程中不显示到期前提醒。

### 10.5 `app/startup/single_instance_guard.cpp`

`SingleInstanceGuard::acquire()` 直接返回 `QSharedMemory::create(1)` 的结果。共享内存只能被一个进程创建，因此同时启动的进程中只有一个能继续。不增加进程遍历、重试、进程间通信或窗口唤起逻辑。

### 10.6 `tools/license_tool/widget.cpp/.ui`

在现有许可证生成区域提供“签发日期”和具体到期日期的年、月、日独立下拉框：

- 打开工具时默认显示本机当天日期；
- 年份范围为本机当前年份前 10 年至后 20 年；
- 年份或月份变化时按实际月份刷新日期选项；
- 允许分别选择年、月、日；
- 具体到期日期早于签发日期时，在写文件前提示“有效期不能早于签发日期，请重新选择”；
- 生成时写入 `LicenseData::issuedDate`；
- 实际文件写入失败时提示检查输出路径、文件权限或文件占用；
- 读取许可证时在文件信息中显示“签发日期：yyyy-MM-dd”，并区分文件无法读取与文件格式无效。

构造函数只获取一次本机日期：签发日期三个下拉框默认设为该日期，具体到期日期三个下拉框默认设为该日期加一年。生成时直接由对应的年、月、日组成 `QDate`。读取具体日期许可证的文件信息时只获取一次上海日期：早于签发日期显示“未到签发日期”，处于签发日期至到期日期范围内显示“有效”，晚于到期日期显示“已超过”；长期有效许可证直接显示“长期有效”。日期表达式直接写在 `widget.cpp` 的现有逻辑中。界面沿用现有表单标签和下拉框样式；控件由 `.ui` 生成，现有逻辑直接通过 `ui` 使用，不修改 `widget.h`。

## 12. 实施阶段

### 阶段 1：许可证签发日期

1. 许可证格式直接升级为 `version=4`；
2. `LicenseData`、读写逻辑和必需字段增加 `issuedDate`；
3. `LicenseTool` 增加签发日期年、月、日下拉选择和读取显示；
4. 删除 `version=3` 判断和所有仅服务于旧格式的内容，不增加兼容解析。

### 阶段 2：日期状态与本地记录

1. 将 `RuntimeGuardResult` 改为 `Valid/Expired/TimeError/DeviceBindingError/Invalid`；
2. 删除 `RuntimeGuardResult::succeeded()` 和 `LicenseDecodeResult::succeeded()`，调用点直接判断枚举状态；
3. 在 `runtime_guard.cpp` 中读取当前 UTC 时刻并换算上海日期；
4. 先比较当前日期与许可证签发日期；
5. 在主程序目录实现唯一日期文件的读取和覆盖写入；
6. 实现日期回拨、到期和剩余天数判断；
7. 删除旧 `valid` 字段、`succeeded()` 和直接使用 `QDate::currentDate()` 的许可证判断。

### 阶段 3：提示与运行中检查

1. 主程序在许可证检查前取得单实例标记，后续进程提示软件已在运行并退出；
2. 启动层按 `TimeError`、`Expired`、`DeviceBindingError` 和 `Invalid` 显示不同提示；
3. 增加到期前 7 天和到期日当天提醒；
4. 24 小时定时器改用统一日期记录和回拨规则；
5. 删除旧的模糊运行期到期提示和直接日期比较。

### 阶段 4：静态收口

1. 检查旧许可证布尔结果和旧日期比较零引用；
2. 检查没有新增兼容接口、时间抽象层或重复日期实现；
3. 检查本地 include、声明和定义一致；
4. 检查 UTF-8、末尾换行和 `git diff --check`；
5. 不运行 qmake、编译、链接、主程序或 `LicenseTool`，统一交给用户验证。

## 13. 验证清单

### 13.1 启动日期来源

1. 具体日期许可证读取当前 UTC 时刻并换算为上海日期；
2. 修改 Windows 显示时区：日期判断仍按上海日期；
3. `LicenseTool` 的签发日期和到期日期默认值使用本机日期，具体日期许可证的文件信息有效期状态使用上海日期；
4. 每次启动检查和每次 24 小时检查分别只获取一次 `currentDate`，该次检查的全部日期比较和记录更新复用同一个值；
5. 主程序解析并保留长期有效许可证的签发日期，但许可证检查流程不获取当前日期、不执行日期判断，也不创建日期记录和 24 小时定时器。

### 13.2 签发日期

1. 打开 `LicenseTool` 时，签发日期的年、月、日默认等于本机当天日期；具体到期日期默认等于本机当天加一年；
2. 签发日期和具体到期日期可以分别选择年、月、日，年份或月份变化后日期选项与实际月份一致；
3. 许可证中不出现 `issuedDate` 字段名或日期明文；
4. 读取许可证时正确显示解密后的签发日期；
5. `LicenseTool` 读取具体日期许可证时，当前上海日期早于签发日期显示“未到签发日期”；
6. `LicenseTool` 读取具体日期许可证时，当前上海日期处于签发日期至到期日期范围内显示“有效”；
7. `LicenseTool` 读取具体日期许可证时，当前上海日期晚于到期日期显示“已超过”；
8. 主程序的当前上海日期早于签发日期：提示时间同步异常并退出；
9. 主程序的当前上海日期等于签发日期：继续执行后续检查；
10. 主程序的当前上海日期晚于签发日期：继续执行后续检查；
11. 具体日期许可证的到期日期早于签发日期时明确提示日期错误并拒绝生成；
12. 主程序解析并保留长期有效许可证的签发日期，但许可证检查流程不获取当前日期或执行日期判断；
13. `version=3` 或缺失签发日期的许可证直接无效，不兼容读取。

### 13.3 日期回拨

1. 具体日期许可证首次进入日期记录检查时，在主程序目录创建与 `license.ini` 同级的 `runtime.dat`，文件名和内容不直接暴露日期用途；
2. 同一天再次启动不重写文件；
3. 日期正常前进时覆盖为较晚日期；
4. 本次日期早于记录日期时显示时间同步异常并退出；
5. 本次上海日期早于记录日期时发现回拨，同一自然日内调早不触发回拨判定；
6. 日期记录无法读取或格式无效时显示时间同步异常并退出；
7. “清空当前软件数据”不删除 `runtime.dat`；
8. 文件内容不出现 `date=`、`yyyy-MM-dd` 日期明文或其他用途标识；
9. 主程序目录无法写入时返回 `TimeError`，不尝试其他保存目录；
10. 具体日期许可证的日期流程未返回 `Valid` 时，不执行首次设备绑定，也不写回 `license.ini`。

### 13.4 提醒和到期

1. 剩余 8 天：不提醒，正常启动；
2. 剩余 7 天：提醒还有 7 天，确认后启动；
3. 剩余 1 天：提醒还有 1 天，确认后启动；
4. 到期日当天：提醒今天到期，确认后启动；
5. 到期日下一天：提示许可证已到期，确认后退出；
6. 每次在 7 天范围内启动都提醒；
7. 连续运行跨过到期日后，24 小时检查提示到期并退出。

### 13.5 失败提示分类

1. `runtime.dat` 无法读取、解析、创建或更新时显示“时间同步异常”；
2. WMI 初始化失败或无法取得有效设备码时显示“绑定设备失败”；
3. 首次绑定无法写回或重新读取 `license.ini` 时显示“绑定设备失败”；
4. 许可证绑定设备与当前电脑不一致时显示“绑定设备失败”；
5. `license.ini` 无法读取、版本错误、缺少必需字段或日期文本无法解析时显示“系统初始化失败”。

### 13.6 单实例启动

1. 缺失或无效许可证时连续启动多次，第一个进程显示“系统初始化失败”，后续进程显示“软件已在运行，请勿重复打开。”；
2. 时间同步异常、许可证已到期或绑定设备失败时连续启动多次，第一个进程显示对应许可证提示，后续进程显示“软件已在运行，请勿重复打开。”；
3. 到期前 7 天内连续启动多次，只有第一个进程显示到期提醒，后续进程显示“软件已在运行，请勿重复打开。”；
4. 主程序已运行时再次启动，后续进程显示“软件已在运行，请勿重复打开。”并退出；
5. 同时启动多个进程时，只有一个进程取得标记并继续；
6. 获取标记的进程退出后，下一次启动可正常取得标记。

## 14. 完成标准

- 具体日期许可证读取当前 UTC 时刻并换算为上海日期；
- 新许可证只使用 `version=4`，签发日期作为独立加密字段；
- 具体日期许可证的当前日期早于签发日期时提示时间同步异常并退出；
- 主程序解析并保留长期有效许可证的签发日期，但许可证检查流程不获取当前日期或执行日期判断；
- 具体日期许可证通过日期检查后才核对当前设备或执行首次绑定；
- 主程序目录中始终只有一个与 `license.ini` 同级的上次检查日期文件；
- 签发日前、日期回拨和日期记录读写失败显示时间同步异常并阻止使用；
- 设备绑定失败显示绑定设备失败并阻止使用；
- 只有当前日期超过到期日时显示许可证已到期并阻止使用；
- 7 天提醒和到期日提醒不阻止使用；
- 到期提示明确，确认后退出；
- 长期许可证不进入日期检查；
- 只有一个主程序进程执行许可证检查、日期记录、设备绑定和主程序启动；
- 后续进程提示软件已在运行并退出；
- 申请码、激活码协议、授权模式、设备码算法和设置 Schema 不变；
- 旧布尔许可证结果、旧直接日期判断和旧模糊到期提示零引用；
- 没有新增兼容层、胶水层、通用时间框架或未被要求的功能。

本方案只处理本机日期获取和系统日期回拨。手工删除或修改 `runtime.dat` 以及修改程序不在本方案范围内。
