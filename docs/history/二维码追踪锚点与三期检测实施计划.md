# 二维码追踪锚点 + 顺序式三期检测实施计划

## 一、目标

在现有 Qt/C++ 工业视觉项目中新增检测模式：

```cpp
const QString BarcodeWordDetectionMode = "barcode_word_detection";
```

界面显示名称：

```text
二维码+三期
```

检测顺序固定为：

```text
现有多模板追踪
→ 选择追踪分数最高的产品模板
→ 使用追踪锚点区域扫描二维码
→ 二维码可读才执行现有日期字库检测
→ 日期检测正确则最终OK
→ 任意步骤失败都最终NG
```

### 当前实施状态

截至当前版本：

- 阶段0至阶段3已完成；
- 阶段4顺序检测代码已接入，程序启动验证通过；
- 阶段4仍需使用无DLL、不可读码、可读码+日期OK、可读码+日期NG等场景完成验收；

- 阶段6硬触发代码已接入，追踪失败会直接形成一次NG，等待硬触发运行验证；
- 阶段7尚未开始。

## 二、不可改变的业务规则

- 工人画的第一个追踪框就是二维码区域。
- 不增加独立二维码框，不增加 `barcode_poly`。
- `tracking_template.bmp` 同时作为追踪模板和二维码扫描区域。
- 日期多边形继续相对于追踪框中心保存。
- 日期检测继续使用现有字符模板、阈值和 `TemplateMatch::run3()`。
- 日期正确判定继续使用：

```cpp
detectNum == targetNum
```

- 本期不优化日期算法。
- 本期不检查日期格式、字符顺序或二维码内容。
- 二维码扫描失败后立即NG，绝不进入日期检测。
- 一件产品只能计数一次、存图一次、输出一次PLC结果。
- 原字库、钢印、OCR和纸巾检测模式必须保持原行为。
- 多模板继续使用当前“最高 `pose.score` Profile”选择逻辑。

## 五、二维码解码接口

### 5.1 数据类型

新增 `BarcodeTypes.h`：

```cpp
enum class BarcodeFormat
{
    Unknown = 0,
    DataMatrix = 1,
    QRCode = 2
};

enum class BarcodeReadStatus
{
    Success,
    NotFound,
    InvalidRoi,
    Timeout,
    DecoderUnavailable,
    InternalError
};

struct BarcodeDecodeOptions
{
    unsigned int formatMask = 1; // Data Matrix
    int roiPaddingPercent = 8;
    int maxDecodeTimeMs = 60;
    bool enableFallback = true;
};

struct BarcodeReadResult
{
    BarcodeReadStatus status = BarcodeReadStatus::NotFound;
    bool readable = false;
    BarcodeFormat format = BarcodeFormat::Unknown;
    QString text;
    std::vector<cv::Point2f> cornersInRoi;
    std::vector<cv::Point2f> cornersInOriginal;
    int elapsedMs = 0;
    QString errorReason;
};
```

二维码成功只表示：

```cpp
解码器返回有效码 && 返回内容非空
```

本期不判断二维码内容是否符合预期。

### 5.2 主程序包装层

新增：

```text
BarcodeDecoder.h
BarcodeDecoder.cpp
BarcodeDecoderApi.h
```

`BarcodeDecoder.h/.cpp`保留为独立包装层和接口参考。

生产检测主流程不直接实例化该C++包装对象，而是在 `Widget` 中使用Windows原生接口从EXE目录延迟加载：

```cpp
LoadLibraryW();
GetProcAddress();
FreeLibrary();
```

只解析以下纯C接口：

```text
BarcodeDecoder_GetVersion
BarcodeDecoder_DecodeLuma8
```

对应主程序函数：

```cpp
bool ensureBarcodeDecoderLoaded();
BarcodeReadResult decodeBarcodeRoi(...);
BarcodeReadResult decodeBarcodeRoiOnce(...);
```

DLL只在二维码+三期模式收到第一张待检测图像后加载，不在程序启动阶段加载，也不形成静态DLL依赖。

DLL缺失、接口缺失或解码器内部错误时：

- 不允许程序崩溃；
- 返回明确错误状态；
- 新模式判为NG；
- 原有模式不受影响。

### 5.3 默认读码策略

快速路径：

```text
8位灰度ROI
仅启用Data Matrix
最多返回1个结果
不主动搜索多角度
不主动反色
不使用重型增强
```

快速路径失败后，在60 ms总预算内依次尝试：

1. 使用同一灰度ROI并开启解码器反色标志；
2. 使用同一灰度ROI并开启解码器强化识别标志。

任意一次成功立即停止。

主程序不再重复执行CLAHE、二倍放大和Otsu等OpenCV增强。二维码追踪ROI已经在进入解码器前完成转正、灰度化和连续内存整理；需要的底层图像增强由读码DLL内部负责。

60 ms是失败路径的验收预算。每次重试前检查累计时间；若真实DLL单次调用本身超过预算，应替换或调整读码DLL，不重构主程序检测流程。

## 六、简化后的代码结构

本次不增加独立检测Worker，不抽取新的模板匹配引擎。

原因：

- 当前字库模式已经具备多模板追踪和日期检测。
- 新需求只需要在日期检测前插入二维码扫描步骤。
- 直接复用 `runWordTemplateDetection()` 最能保证日期算法不发生变化。
- 减少线程、队列、元类型和结果排序带来的改动风险。

核心入口：

```cpp
void Widget::runBarcodeWordDetection(
    cv::Mat *image,
    const DetectionPose &pose,
    const WordTemplateProfile &profile);
```

固定实现：

```cpp
if (!pose.valid) {
    finalizeBarcodeWordNg(TrackingNotFound);
    return;
}

OrientedTrackingRoi roi =
    prepareOrientedTrackingRoi(*image, pose, paddingPercent);

if (!roi.valid) {
    finalizeBarcodeWordNg(InvalidBarcodeRoi);
    return;
}

if (!ensureBarcodeDecoderLoaded()) {
    finalizeBarcodeWordNg(DecoderUnavailable);
    return;
}

BarcodeReadResult barcode =
    decodeBarcodeRoi(roi.grayRoi, options);

if (!barcode.readable) {
    finalizeBarcodeWordNg(BarcodeUnreadable);
    return;
}

// 只有扫码成功才允许执行现有日期检测
runWordTemplateDetection(
    image,
    pose,
    profile.digitTemplates,
    profile.digitTemplateTargetIndexes,
    profile.settings.targetText,
    QString::number(profile.settings.imageThreshold),
    profile.name);
```

7. 最后才替换读码DLL。

## 八、最终验收标准

功能完成必须同时满足：

- 工人只画二维码追踪框和日期多边形；
- 二维码框保存为 `tracking_template.bmp`；
- 多模板继续自动选择最高分Profile；
- 运行时首先扫描追踪锚点区域；
- 扫码失败立即NG；
- 扫码失败时日期检测明确显示“未执行”；
- 扫码成功才调用原字库算法；
- 日期检测结果与修改前一致；
- 一件产品只有一次计数；
- 一件产品只保存一次结果图；
- 一件产品只输出一次PLC结果；
- 软触发和硬触发均可用；
- 200件/分钟下无持续积压；
- 原字库、钢印、OCR和纸巾检测没有回归。

## 九、本方案明确不做的内容

- 不优化日期检测算法。
- 不检查日期格式或日期先后关系。
- 不检查二维码内容是否正确。
- 不新增独立二维码绘制框。
- 不新增后台Worker和检测任务队列。
- 不重写 `TemplateMatch::run3()`。
- 不升级Qt、OpenCV、PaddleOCR或MSVC工程。
- 不在命令行完整编译工程。
- 不由Codex下载或编译第三方读码库。
